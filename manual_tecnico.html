1. Introducción y Descripción General

1.1 Propósito del sistema

Otto Ninja Pro Controller es una aplicación web/móvil de control remoto en tiempo real diseñada para operar el robot humanode Otto Ninja equipado con un microcontrolador ESP32. Permite enviar comandos de movimiento, ejecutar secuencias de combate, reproducir efectos de sonido y ajustar la calibración mecánica de los servomotores, todo desde una interfaz táctil intuitiva optimizada para orientación horizontal.

1.2 Alcance y audiencia objetivo

Este manual está dirigido a:

  • Desarrolladores que necesiten mantener, extender o depurar la aplicación.
  • Técnicos de laboratorio que configuren el entorno de despliegue.
  • Instructores de robótica que integren el controlador en actividades educativas.

3.2 Instalación y ejecución local

# 1. Clonar el repositorio
git clone https://github.com/Maykhol10/otto-ninja-controller.git
cd otto-ninja-controller

# 2. Instalar dependencias
npm install

# 3a. Servidor de desarrollo (con hot-reload)
npm run dev     # Abre http://localhost:8000

# 3b. Servidor de producción estático
npm start       # npx serve .
ℹ️ Nota sobre CORS
La aplicación envía peticiones HTTP a la IP del ESP32. Si se sirve desde localhost, los navegadores modernos requieren que el ESP32 incluya el header Access-Control-Allow-Origin: * en sus respuestas.

3.3 Compilación para Android (APK)

# Sincronizar assets web con el proyecto Android
npm run android:build
# Equivale a: npx cap sync android && npx cap open android

# Generar APK debug directamente desde CLI
npm run android:apk
# Equivale a: cd android && ./gradlew assembleDebug

# El APK resultante se encuentra en:
# android/app/build/outputs/apk/debug/app-debug.apk
⚠️ Configuración de red en Android
El archivo capacitor.config.json establece el esquema HTTP (no HTTPS) para permitir peticiones a la IP local del ESP32 desde la APK Android. No modificar sin revisar las políticas de seguridad de red de Android.

3.4 Configuración del ESP32

El ESP32 debe estar programado con un firmware que:

  • Se conecte a la red WiFi local y obtenga/use una IP estática conocida.
  • Exponga un servidor HTTP en el puerto 80.
  • Responda a los endpoints definidos en la Sección 4.
  • Incluya el header Access-Control-Allow-Origin: * en todas las respuestas.
✅ Conectar la app al robot
En la pantalla principal de la app, escribir la IP del ESP32 en el campo de texto (p. ej. 192.168.1.105) y pulsar Conectar. La app verificará el endpoint /status para confirmar la conexión.

4. Protocolo de Comunicación (API REST)

4.1 Convenciones generales

  • Todas las peticiones son HTTP GET a http://<IP_ESP32>/<endpoint>.
  • Los parámetros se pasan en el query string: ?param=valor.
  • Las respuestas se esperan en JSON; cualquier respuesta no vacía se considera éxito.
  • Timeout por petición: 2 000 ms (controlado por AbortController).
  • En caso de error de red, la función registra el error en el log pero no reintenta.

4.2 Endpoints disponibles

GET /status

Descripción: Verificación de conectividad (ping).

Parámetros: ninguno.

Respuesta esperada: cualquier respuesta JSON (p. ej. {"ok":true}).

Uso en app: función connect().

GET /mode

Descripción: Cambia el modo de desplazamiento del robot.

Parámetros:

Ejemplo: GET /mode?cmd=rodar

Ejemplo: GET /walk?cmd=forward

4.3 Sistema de debounce y throttling

Para evitar la saturación del ESP32, la aplicación implementa dos mecanismos de control de frecuencia de comandos:

MecanismoIntervaloAplica a
Cooldown global 400 ms Todos los comandos de acción (walk, arms, head, attack, buzzer)
Throttle de joystick 100 ms Envío continuo de posición X/Y del joystick analógico
Deduplicación — No envía el mismo comando walk si ya estaba activo 
// Fragmento del sistema de debounce (app.js)
function canSendCommand(commandType) {
  const now = Date.now();
  const lastTime = state.lastCommandTime[commandType] || 0;
  if (now - lastTime < 400) return false;
  state.lastCommandTime[commandType] = now;
  return true;
}

5. Módulos Funcionales

5.1 Sistema de Conexión

La función connect() (app.js:275) gestiona la conexión al ESP32:

  1. Lee la IP del campo de texto del header.
  2. Valida que no esté vacía.
  3. Realiza una petición a /status con sendRequest().
  4. Si responde correctamente: actualiza el indicador visual a verde, guarda la IP en state.esp32IP y habilita todos los controles.
  5. Si falla: muestra estado "Desconectado" en rojo.
ℹ️ Persistencia de IP
La IP se almacena en localStorage bajo la clave esp32IP, de modo que se restaura automáticamente al recargar la aplicación.

5.2 Controles de Juego: Joystick y D-Pad

El panel de controles tiene dos modos seleccionables mediante tabs:

Modo Rodar (Joystick Analógico)

Implementado en app.js:713–937. Utiliza la Pointer Events API para capturar input táctil y de ratón de forma unificada.

  • Radio máximo: 100 px desde el centro.
  • Normalización: Los valores X/Y se normalizan a rango [-100, 100].
  • Frecuencia de envío: máximo 10 actualizaciones/segundo (100 ms).
  • Pointer capture: se usa setPointerCapture() para mantener el arrastre fuera del elemento.
// Ciclo de actualización del joystick (simplificado)
function sendJoystickUpdate() {
  const now = Date.now();
  if (now - state.joystick.lastUpdate < 100) return;
  state.joystick.lastUpdate = now;

  const x = Math.round(state.joystick.x);
  const y = Math.round(state.joystick.y);
  sendRequest('joystick', { x, y });
}

  • La app está optimizada para orientación horizontal (landscape).
  • El meta tag viewport y la configuración Capacitor fuerzan landscape en Android.

8. Solución de Problemas

SíntomaCausa probableSolución
El botón "Conectar" queda en rojo IP incorrecta, ESP32 apagado o fuera de red Verificar que el ESP32 esté encendido y conectado al mismo WiFi. Comprobar la IP en el router.
Los comandos no llegan al robot Error CORS o firewall Confirmar que el firmware del ESP32 incluye el header Access-Control-Allow-Origin: *.
El joystick no responde en móvil Touch events no capturados Verificar que el navegador soporte Pointer Events API. Usar Chrome Mobile ≥ 100.
Los ataques no se ejecutan Ataque no seleccionado o cooldown activo Seleccionar el ataque en el panel Ataques y esperar 400 ms entre comandos.
El robot se mueve de forma incorrecta en modo walk Servos descalibrados Usar el panel Calibrar para ajustar los offsets de cada pierna.
No se escuchan sonidos Número de canción fuera de rango o buzzer deshabilitado en firmware Verificar que el firmware soporte el número de canción seleccionado (1-16).
La APK Android no conecta al ESP32 Política de red HTTP bloqueada Verificar que capacitor.config.json tenga "scheme": "http" y que la APK esté instalada con permisos de red local.
Gradlew falla en la compilación JDK incompatible o SDK de Android desactualizado Usar JDK 17. Ejecutar npx cap sync android antes de compilar.
La interfaz muestra orientación incorrecta Falta de soporte landscape en el dispositivo Forzar rotación landscape en configuración del dispositivo o verificar el meta tag viewport.
🔴 Advertencia de seguridad
La API REST del ESP32 no implementa autenticación. No exponer la red WiFi del robot a internet. Usar exclusivamente en redes locales cerradas (laboratorio, evento).
